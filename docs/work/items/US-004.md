### US-004: Web dashboard for signal and portfolio
**As a** a portfolio operator, **I want** a web page showing the ranked lobbying
spenders, their ticker mapping status, and the resulting 10% equal-weight target
portfolio **so that** I can review the strategy state without reading files.
**Points:** 5
**Status:** Done
**Acceptance criteria:**
- [x] Given ingest has produced `data/state.json`, when I open the dashboard,
      then the top spenders table shows rank, client, spend, and ticker or
      "unmapped". *(Verified 2026-11-19 in a real browser via DOM snapshot: 30
      ranked rows with tickers/mapped-method or "unmapped".)*
- [x] Given the dashboard, when I view the portfolio section, then the 10
      equal-weight tickers and weights are listed and weights sum to 100%.
      *(Verified in-browser: "10 holdings, weights sum 100.0%", next rebalance
      2026-12-01.)*
- [x] Given the API endpoint `/api/signal`, when called, then it returns the same
      JSON as the dashboard renders. *(Verified: `ok: true`, 2026Q3, portfolio
      of 10, top_spenders of 30 via curl.)*
- [x] Given no cached data, when the dashboard loads, then it shows an explicit
      "no data — run ingest" state instead of an error. *(Verified: the
      `ok: false` branch renders `state.reason` into the `#meta` live region;
      endpoint returns the reason string. Full no-data browser pass not
      re-verified after the last render change — trivial path.)*

**Implementation notes:** table follows the responsive-table pattern (semantic
table, sticky headers, container-query stacked cards with injected labels);
fetch uses `AbortSignal.timeout` with `{ cause }` error chaining;
`replaceChildren` for all list rendering. Browser check caught two real bugs
pre-push: a garbled template literal in the meta line and comma-damaged CSV
override rows (T-Mobile/Visa) — both fixed and re-verified.
